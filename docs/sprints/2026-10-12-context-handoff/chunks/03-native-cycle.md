temporary repositories/private tmux. Record clear command receipt, native epoch transition,

## Adapter and executor contract

Implement a narrow native adapter with `Probe`, `InspectPrompt`, `EnterClear`,
`VerifyReset`, `BootstrapPickup`, `EnterPickup` and `VerifyPickup` operations. Each returns
typed evidence or a fixed unavailable/failure reason. The executor receives the pinned
cycle, never model-supplied shell text. Fixed command bytes come from the family adapter.

1. Resolve the stored unresolved tmux socket and exact pane; compare current host/start,
   process ancestry and no intervening agent immediately before every input. Reject a
   busy shell/background task as reset-ready even if display activity is idle.
2. Verify an empty suitable prompt and inspect tmux mode. Return a verified pane from
   copy mode as part of the enabled operation, capture again, then proceed. A selection,
   pending command or native dialog follows its observed adapter case.
3. Commit the input intent; enter literal bare command text; inspect the input field;
   submit Enter separately; read back command processing. Never double Enter by rule.
   Recheck Disable/revision before submission and record any raced or uncertain effect.
4. Verify native reset epoch independently of Koinon registration. Reused Claude MCP
   identity can remain valid under its checked host. For changed keys use existing native
   succession and its reported wait/refusal; never retire or move a participant to force it.
5. Bootstrap canonical pickup only through the proven native path, then enter bare
   `/pickup` or `$pickup`. Do not append task prose. Pin catalog/item digests for the cycle;
   a bootstrap failure stops before clear whenever it can be determined in advance.
6. Handle recognized completion menus, reset confirmations and startup/pickup alerts with
   their native options and read-back. Native permission decisions use the existing task
   authorization and permission interface. For a prompt choice the adapter cannot resolve,
   show the current stage/options to the maintainer through the authenticated dashboard;
   its compared-revision response is applied only to that same observed prompt. Never
   infer a weaker permission mode from Enable or from a peer message.
7. Await the receiving model's current own-cycle pickup report after its canonical pickup
   procedure. Verify the intended artifact and restored task/pause state in native evidence,
   current epoch/host/pane and registration/participant. Carry Enable only on complete
   same-pane/same-participant success; otherwise end it with the actual failure reason.

## Crash and dashboard behavior

Inject crashes around literal text, Enter, native reset and receipt commits. On restart,
inspect rather than replay pending intents. Proven native receipts may advance the same
cycle; ambiguous output ends it as uncertain and retains the saved artifact metadata.
No status refresh submits a native command. Serialize by exact host/pane so two callers,
duplicate requests or overlapping roles cannot type into the same target concurrently.

Finish capability display and session Enable, family settings, live stage/history, source
ages, missing-skill fallback indication, fixed reasons and prompt response UI. Existing
login/Host/Origin/CSRF apply; preserve focus during fragments. Audit each transition and
response without prompt/body/native-ID leakage. A transport error is distinct from a
proven native failure. Unsupported families retain clear monitoring/query results.

Run the entire DoD matrix and required publication checks. Native model proof is separate
from disposable service CI and must cover every platform/version declared available.
Use exact-head independent peer/refusal review and squash auto-merge. Close #196 only after
merged behavior and the native matrix satisfy the decision; incomplete platform or bootstrap
evidence remains an explicit open acceptance item.
